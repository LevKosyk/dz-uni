### 1. GraphQL

GraphQL розв’язує задачу отримання та передачі даних через API, а її кінцевими користувачами є розробники клієнтських і серверних застосунків. Вона дозволяє клієнту самому вказати, які саме поля та пов’язані дані потрібно отримати від сервера. Без GraphQL для цього часто довелося б створювати декілька REST-запитів або окремі API-ендпоінти. Межа GraphQL у тому, що вона призначена саме для роботи з API та даними, тому нею не варто реалізовувати основну бізнес-логіку сервера.

### 2. Prisma Schema Language

Prisma Schema Language використовується для опису структури бази даних у Prisma: моделей, полів, типів даних, зв’язків між таблицями та інших параметрів. Її кінцевим користувачем є backend-розробник, який працює з базою даних через Prisma ORM. Вона робить створення та зміну структури бази значно простішими, оскільки замість великої кількості SQL можна описати моделі у зрозумілому декларативному форматі та використати Prisma Migrate. Її межа - це опис моделей і конфігурації Prisma, тому нею не варто писати бізнес-логіку сервера.

### 3. Redis Lua

Redis Lua використовується для написання невеликих скриптів, які виконуються безпосередньо всередині Redis. Її кінцевим користувачем є backend-розробник, якому потрібно виконати декілька операцій з даними Redis. Вона спрощує складні послідовності команд: замість декількох запитів між сервером і Redis можна виконати потрібну логіку одним скриптом. Межа Redis Lua полягає в тому, що вона підходить для коротких операцій над даними Redis, але не для створення всього backend-сервера, великих програм або складної бізнес-логіки.
